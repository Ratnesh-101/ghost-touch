# WA-A2: accessibility semantics audit (Correct, Teach, Build, Saved, Settings, Ask)

Read-only audit. Static review of code and CSS only; nothing was run on a phone or in TalkBack, and no files other than this report were changed. Start, Capture and Explore were skipped as instructed, except that the Ask flow lives inside `Explore.tsx`, so I read it.

Read first: `CLAUDE.md`, `.kiro/steering/product.md`, `tech.md`, `structure.md`, `review.md`, `verify.md`.

Owner column: every file below is outside the Kiro-owned list in AGENTS.md, so the builder (Antigravity) owns all fixes. Nothing here needs a change in `frontend/src/core/**`, the schema, or the tuned haptic values.

## Findings

| ID | Sev | File:line | Problem | Suggested fix | Owner |

| A2-01 | Med | `frontend/src/components/LabSettings.tsx:323` (trap), `:518` (hidden block) | The Tab trap collects focusable elements with `querySelectorAll('button:not([disabled]), ...')`. That also matches the buttons inside `#lab-settings-more-content`, which has `hidden` while "More settings" is collapsed (the default). So `last` is a button that cannot take focus. Tab from the last visible control (the "More settings" toggle) never equals `last`, so the trap does not wrap and focus leaves the dialog into the page behind it. On a keyboard or switch setup this breaks the modal. | Filter out elements inside a `[hidden]` ancestor (e.g. `el.closest('[hidden]') === null`) or `offsetParent !== null`, or render the "more" block only when `moreOpen`. | Antigravity |
| A2-02 | Med | `frontend/src/screens/Correct.tsx:755` (and `:776`, `:797`, `:818`, same pattern) | Element picker buttons are named `"Selected point: A"` (`correct.selectedPoint` = "Selected point") for every point, selected or not, and also carry `aria-pressed`. TalkBack reads "Selected point: A, toggle button, not pressed", which contradicts itself. The same applies to segment, polyline and bar buttons. | Use a neutral noun for the name ("Point: A", new i18n keys) and let `aria-pressed` carry the state. Keep "Selected point" for the announcement after selection only. | Antigravity |
| A2-03 | Med | `frontend/src/screens/Teach.tsx:687` with `frontend/src/components/teach/TeachCanvas.tsx:388` | In Teach the only way to select a vertex or segment, or to pick the two ends of "Add edge", is a pointer tap on the canvas. There is no list of elements like the one Correct has (`Correct.tsx:741`). Keyboard arrows nudge only after a selection exists, and a selection can only be made by pointer. With TalkBack or a switch, the canvas `role="img"` double-tap fires at the element centre, so only a vertex that happens to sit at the centre can be chosen. Edges are therefore not buildable without touch. Teach is a secondary (sighted teacher) tool, so this is Med rather than High. | Add the same selectable element list as Correct (buttons named by label), wired to `onSelect` and the Ghostwriter `pickPoint` event. | Antigravity |

| A2-06 | Med | `frontend/src/screens/Build.tsx:262-264`, `:215-219` | The Build form has no focus management. ## Areas checked and found good

- **Saved diagrams (`SavedDiagrams.tsx`, `saved.css`):** `main` landmark, heading focused on mount, list semantics correct, thumbnails hidden from AT, every button name starts with its visible text plus the diagram title ("Open <title>"), `StatusText` used so there is no double announcement, empty state spoken, 48 px targets set in CSS, header and controls wrap. Only finding is A2-05.
- **Language and rate selectors:** `role="group"` with names, `aria-pressed`, one spoken confirmation each, 48 px targets.
- **Correct (`Correct.tsx`, `correct.css`):** `main`, heading focus on mount, `StatusText`, labelled input (visually-hidden label), all buttons use `AccessibleButton` and `min-height: var(--gt-target)`, no fixed heights on text containers (status card uses `min-height` only), toolbars wrap. Findings are A2-02, A2-08, A2-09.
- **Teach (`Teach.tsx`, `teach.css`, `VerifyForm`, `SharePanel`, `LoadModal`):** labelled form fields with visible labels, `aria-required`, `role="alert"` on axis and share errors, honest-copy notices, dialog with `aria-modal`, labelled title, focus trap, Escape, focus returns to the Load button on close, 48 px inputs and buttons in CSS. The `role="toolbar"` has a name but no arrow-key roving (acceptable for a wrapping button row).
- **Ask (inside Explore):** the text input has a hidden label, `maxLength`, busy state disables controls but focus is restored explicitly afterwards (`Explore.tsx:1392-1399`, `:1488-1492`), and errors are spoken and shown. The a11y tree buttons have 48 px minimums and `pointer-events: none`, which is correct for pass-through since TalkBack activates them through accessibility actions. No defect found.
- **Settings sheet (apart from A2-01/A2-12):** `role="dialog"`, `aria-modal`, `aria-labelledby`, focus moves to the close button on open and returns to the launcher on close, Escape works, switches use `role="switch"` with `aria-checked` and hint text via `aria-describedby`, 48 px sizes, sheet scrolls (`max-height: 85vh`).

## Not verified

- TalkBack behaviour was not tested; statements about double announcement and focus loss come from reading the code and from the comment in `StatusText.tsx` describing the same mechanism.
- Whether Chrome on Android hides background content from TalkBack for `aria-modal` dialogs (Settings sheet, Teach Load modal) is unverified. Neither dialog sets `inert` on the page behind it.
- 200% clipping was judged from CSS only. The Playwright probe already covered Start, Capture and Explore; none of Correct, Teach, Build, Saved or Settings was measured.
