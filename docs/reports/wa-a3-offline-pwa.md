# WA-A3: Offline sample path, PWA cache, spoken offline/error lines, cold or down backend

Read-only audit. Read CLAUDE.md and `.kiro/steering/*.md` first. I read `frontend/vite.config.ts`, `frontend/dist/sw.js` (an existing build; I did not rebuild), `src/api/{scene,health,ask}.ts`, `src/flow/{capture,svara}.ts`, `src/drivers/swUpdate.ts` and the `capture.*` and `ask.*` strings in `src/i18n/index.ts`. I ran no tests and could not use a device.

## What is good
- **Sample path works offline by design.** `loadSample(id)` with no `fetchImpl` returns the in-bundle `BUNDLED_SAMPLES` object (`src/api/scene.ts:470-489`). It makes no network call, and `Capture.tsx:257` uses that form. This is consistent with the probe result.
- **Precache is complete for the shell.** The built `dist/sw.js` precaches `index.html`, the JS and CSS, both Atkinson fonts, the icons, `samples/*.json` and the pdf.js worker (1.27 MB, under the 3 MB limit). It also registers a `NavigationRoute` bound to `index.html`, so a cold offline launch of the installed app works.
- **`registerType: 'autoUpdate'`** gives skipWaiting and clientsClaim. `swUpdate.ts` ignores the first controllerchange and reloads at most once per session, which avoids a reload under a finger.
- **Cold-start handling is thought through.** Scene requests allow 60 s, then speak `capture.waking`, then retry within a 120 s total budget. 502/503/429 get a jittered Retry-After retry. Each failure kind has its own spoken line. `processImageFile` always stops the progress tone in `finally`.
- **Offline wording is correct.** `capture.errorOffline` and `ask.errorOffline` both say samples still work. `warmBackend` swallows every error and skips when offline.
- **Missing voice mp3s fail quietly.** `public/voice/` holds only `manifest.json`, and `flow/svara.ts` swallows missing-file failures (lines 143, 173, 200, 211), so nothing breaks.
