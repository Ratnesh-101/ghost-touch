# Lane b6-lowend-perf (AUDIT ONLY)
Read `docs/briefs/audit-b-common.md` first. Report: `docs/reports/audit-b6-lowend-perf.md`.
Scope: behaviour on a budget Android phone (slow CPU, weak vibration motor, 2 to 3 GB RAM). Explore `pointermove` hot path (allocations per event, hit-test cost on a 2000-point polyline, canvas redraw frequency, devicePixelRatio scaling), `requestAnimationFrame` loops left running after unmount, audio/oscillator and AudioContext lifecycle (suspended on Android Chrome until a gesture, leaks on screen change), vibration call rate limits (Chrome throttles `navigator.vibrate`), timers and listeners not cleaned up (`setInterval`, `addEventListener`, SpeechRecognition, camera streams), image downscale memory (1600 px canvas, large HEIC/JPEG), IndexedDB payload sizes, bundle size and first-load cost (run `npm --prefix frontend run build`, report chunk sizes), long tasks. Give estimates only where you can derive them from the code; mark device-dependent claims UNVERIFIED.
