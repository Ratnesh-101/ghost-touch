# Lane e2e-canvas-stable (Playwright regression test for the Explore canvas growing during a hold)
Read AGENTS.md first. Never open `.env*`. TEST FILES ONLY: create `frontend/e2e/explore.canvas-stable.spec.ts` (and a tiny helper in `frontend/e2e/` if needed) and `docs/reports/agy-e2e-canvas.md`. Do NOT edit anything under frontend/src, frontend/tests, `.kiro/`, `frontend/playwright.config.ts` or package.json (the supervisor set Playwright up: two projects, Galaxy S24 384x832 DPR 3 and S24+ 412x915 DPR 3.5, touch, Android Chrome UA, service workers blocked, webServer builds and previews on :4173). Create the report FIRST (Status IN PROGRESS, DONE at the end, DEFERRED list). One BUILD_LOG entry (tool = "agy, reviewed by Claude").

Bug (P0, Galaxy S24+, the INSTALLED app / PWA, standalone, no URL bar; not yet seen in the website): on the first double-tap-hold-drag in Explore the status line shows "First hold: dx=-74.4px, dy=-47.2px from centre" and the diagram canvas then grows taller continuously for about 7 s. The triangle drifts down, gets cut off, and the Ask/Correct/Back buttons are pushed off-screen. Expected: the canvas has a fixed size for the whole session and the page never scrolls or resizes during a hold. A CSS-only fix (canvas position:absolute; inset:0) is already on main (5616cd5); this test must tell us whether the bug still exists.

Write these tests (run for both projects automatically):
1. Open `/`, get to Explore with the sample "Right triangle" (read src/screens/Start.tsx, Capture.tsx and App.tsx for the real buttons and their accessible names; use getByRole with names, no brittle CSS selectors; the samples work offline, no backend call). English.
2. Record `canvas.boundingBox()` (the Explore canvas element, class gt-explore__canvas), `document.scrollingElement.scrollHeight`, `window.scrollY`, and the bounding boxes of the Ask, Correct and Back controls.
3. Hold-and-drag for 5 s with RAW touch events through a CDP session (`const cdp = await page.context().newCDPSession(page)`, `Input.dispatchTouchEvent` touchStart, many touchMove steps along a path across the triangle, wait, touchEnd; Playwright's `touchscreen` only supports taps). Cover (a) a finger that starts away from the centre, and (b) the TalkBack-style flow: a single pointer that starts at the canvas centre (double-tap-and-hold then drag, with the pass-through announcement text appearing in the status line). Sample the canvas boundingBox, scrollHeight and scrollY at least every 250 ms during the hold and after touchEnd.
4. Assert for every sample: the canvas boundingBox width and height are identical to the baseline (tolerance 0.5 px), `window.scrollY` is unchanged, scrollHeight does not grow, and Ask, Correct and Back stay fully inside the viewport (boundingBox within 0..innerHeight). Add one assertion that the status line's box height did not change either.
5. Installed-app (standalone) scenarios, because the real bug is in the PWA: (a) during a hold, change the viewport height by about 56 px and back (`page.setViewportSize`), simulating the URL bar or navigation bar showing and hiding, and assert the canvas does not keep growing (after the viewport returns to its original size the canvas box must equal the baseline); (b) rotate once (swap width and height, then back) and assert the canvas returns to its baseline size; (c) a longer 10 s hold.
6. Failure messages must print the sampled heights over time so a regression shows the growth curve.
Mark nothing `skip`. Use `test.describe` per scenario. TypeScript strict (no `any`), import only from '@playwright/test'.
The test is expected to FAIL on a build from before 5616cd5 (growing canvas); you cannot run it (no shell), so say in your report exactly what each assertion proves and how the supervisor can check it by running `npx playwright test` against `git checkout 5616cd5~1` in a throwaway worktree. Done when the spec file is complete, type-correct by inspection, and the report is DONE.
