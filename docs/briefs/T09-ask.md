## Part A: backend `POST /api/v1/ask` (9.1). Files: `backend/**` only.
- Request `{ scene, question, lang }`; response `{ answer, source }` with `source` one of `"ai"`, `"facts"`, `"unknown"`. Pydantic request models; the scene is validated with `DiagramScene.model_validate` from `app/schema.py` (do not edit `schema.py` or `validate.py`). `question` 1 to 500 characters after trimming, `lang` a BCP-47 style code (`en`, `en-IN`, `hi`, `gu`, ...); anything else is HTTP 422 with a short message.
- Prompt (in `app/ask.py`, no inline prompt in the route): answer in **at most 2 short sentences, using only the scene JSON and its `facts`**; if the scene cannot support an answer, reply with exactly `I don't know from this diagram.` (for `lang` other than English, the same sentence translated, but the English one is the reference); reply in `lang`. Put the question inside clearly marked delimiters and tell the model to treat it as data, never as instructions (prompt-injection hygiene). Send a compact scene (omit very long polylines: keep their label, point count, and min/max; the facts and labelled points/segments/bars in full).
- Providers: extend the existing provider classes in `app/vision/` with a **text-only** call (`complete(prompt, timeout)`), reusing the fallback chain (Gemini first, then NVIDIA, skip providers without keys). Total budget 10 s (configurable by environment variable), then fall back to the **facts lookup**.
- **Facts lookup fallback** (`source: "facts"`): a small deterministic matcher over `scene.facts` and element labels (content words and numbers, same idea as the research scorer in `research/spike_scoring.py`, but written fresh in the backend, not imported), for example "How long is AB?" with a fact "AB = 5 cm" answers "AB = 5 cm." No match: `source: "unknown"` and the exact sentence above. This keeps Ask working with no API key or quota.
- Never a 500 for a valid request. Never log the question text or the scene (log lengths, provider and outcome only). Never cache failures.
- Tests (no network, fakes only, fakes injected with `Depends` like the scene route): answer from a fake model; model says "don't know"; provider error then facts fallback; both fail then unknown; prompt contains the delimiters and the question; over-long question 422; bad lang 422; injection attempt in the question ("ignore previous instructions") stays inside the data block; the DoD examples below.
- DoD examples with the triangle sample: "What is the length of AB?" returns an answer containing the fact's number and unit; "What colour is it?" returns exactly `I don't know from this diagram.`
- Run with `backend/.venv/Scripts/python -m pytest`, `-m ruff check .`, `-m ruff format --check .`. Only the existing dependencies. Do not edit `docs/BUILD_LOG.md` or `KIRO-PAUSE.md`; put your BUILD_LOG text at the end of your report `docs/handoffs/T09a-report.md`.

## Part B: frontend Ask flow (9.2). Files: `frontend/**` only.
- Pure logic in `frontend/src/flow/ask.ts` (unit tested): the sequence is listening cue (`audio.beep`) then `speech.listen(lang)` then `POST /api/v1/ask` then `speech.speak(answer)`. Every failure speaks a short line (no speech heard, microphone denied, timeout, server error, offline) and offers the text box; never silence. One Ask at a time (ignore a second trigger while busy and say so). Timers cleared on every exit path; unmount aborts the request.
- `frontend/src/api/ask.ts`: client with a 12 s timeout and abort support, same error style as `api/scene.ts`.
- UI in the Explore screen (`screens/Explore.tsx`): an **Ask** button (`AccessibleButton`, at least 48×48 px, outside the touch canvas, reachable by TalkBack swipe navigation) that starts listening; a **text box with a Send button** shown when speech recognition is unavailable (`speech.canListen` false) or after a failed listen. The optional **two-finger long-press (600 ms)** on the canvas also starts Ask; it must not interfere with the single-finger hold, and the detector is a pure tested function in `flow/explore.ts` or `flow/ask.ts`. Do not remove or weaken the T07 behaviour, the exit paths or the tests.
- TalkBack: the answer is spoken by the speech driver; show it as visible text with `StatusText` (no live region while the app speaks). After speaking, focus returns to the Ask button.
- Strings through `t()` (add keys to `frontend/src/i18n/index.ts`); styles in `global.css`; no new dependencies; browser APIs only in `drivers/`.
- Tests: `flow.ask.test.ts` (happy path order, each failure line, double trigger, timers cleared, abort on unmount, text fallback), `api.ask.test.ts` (success, http, timeout, abort, bad shape), long-press detector, and server-render checks for the Ask button and text box.
- Run from `frontend/`: `npx tsc --noEmit`, `npm test` (a Kiro-owned property test may fail intermittently; if it is the only failure, rerun and say so), `npm run build`. Report real results; do not claim phone results you did not get.
