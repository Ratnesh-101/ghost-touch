## Part 0 (do this FIRST, it is small): unify the retry settings parsing
`PROVIDER_RETRIES` and `PROVIDER_RETRY_BACKOFF_SECONDS` are parsed twice: in `backend/app/vision/chain.py` (`parse_provider_retries`, `parse_provider_retry_backoff`, used when the chain is constructed) and again in `backend/app/main.py` (the cached chain gets `chain.retries = ...` and startup validation logs repeat it). Known defect: with an INVALID value (for example `abc`) `main.py` logs "using default 1" but the chain keeps 0 retries, because an `except ValueError: pass` leaves the constructor default. Fix: make `build_chain_from_env()` (in `backend/app/vision/__init__.py`) apply both settings through the existing parse functions in `chain.py`, so that: unset gives retries 1 and backoff 0.8; a valid value is used; an invalid or negative value gives the default (1 and 0.8) with ONE warning log. The plain `ProviderChain(...)` constructor must keep working with explicit arguments for the existing tests (read `backend/tests/test_chain.py` and `test_chain_retry.py` first). Remove the duplicated parsing and warnings from `main.py` (leave the validation of the OTHER variables exactly as it is). Add `backend/tests/test_chain_env.py`: unset gives 1 and 0.8; `PROVIDER_RETRIES=0` gives 0; `abc` gives 1; `-3` gives 1; `PROVIDER_RETRY_BACKOFF_SECONDS=abc` gives 0.8; `0` gives 0; the cached chain used by the app has the same values.

## Fix these (in this order; each with tests)
1. SEC-01, concurrency cap: add a process-wide `asyncio.Semaphore` around the heavy part of `POST /api/v1/scene` (vision chain plus OpenCV). Size from env `SCENE_MAX_CONCURRENCY` (default 2, invalid or below 1 falls back to 2 with one warning). A request that cannot get a slot waits up to `SCENE_QUEUE_WAIT_SECONDS` (default 6) and then gets HTTP 503 with a `Retry-After: 5` header and a JSON body in the same shape as the other errors (read how existing error responses look; include a short human `reason`). The semaphore must always be released (use `async with` or try/finally), including on exceptions and cancellation, and must NOT be held while parsing the upload body. Tests: 3 concurrent requests with a slow fake provider and cap 2 means the third waits then succeeds if a slot frees within the wait, and gets 503 with `Retry-After` when it does not; the slot is released after an exception.
2. SEC-02, pixel limit: lower `MAX_IMAGE_PIXELS` to 12_000_000 (the frontend already downscales photos to 1600 px on the long side before upload, so real traffic is far below this). Update the existing tests that assert the old 40 MP boundary, and add one that a 12.1 MP image is rejected with the same error shape as before and an 11 MP image is accepted.
3. SEC-04, EXIF: FIRST reproduce before changing anything. Check how the image is decoded in `raw_mode.py` and `image_utils.py` (which `cv2.imdecode` flags; OpenCV applies EXIF orientation by default for JPEG unless `IMREAD_IGNORE_ORIENTATION` is passed). Build a tiny JPEG test fixture in the test itself (Pillow is not guaranteed: write a minimal JPEG with an EXIF orientation 6 tag by hand, or use `cv2.imencode` plus inserting an APP1 EXIF segment) and assert what the decoded shape and the dimension sniffing report. If the bug is real (the sniffed dimensions and the decoded array disagree, or the decode ignores orientation), fix it minimally and test it; if it is NOT real, change nothing and write that plainly in the report with the evidence.
4. SEC-06, `POST /api/v1/validate` must apply the same structural limits as `/api/v1/ask` (reuse its `_check_scene_size` or equivalent: maximum points, segments, string lengths; same HTTP status and error shape). Tests for each limit.
5. SEC-07 and SEC-08: add a small middleware that sets `X-Content-Type-Options: nosniff` on every response and `Cache-Control: no-store` on JSON API responses (not on the Raw Mode image processing, there are none); and disable `/docs`, `/redoc` and `/openapi.json` when env `ENVIRONMENT` is `production` (default stays enabled so local development and the existing tests are unaffected). Add `ENVIRONMENT: production` to `render.yaml`. Tests for both modes.
6. SEC-09: add `RATE_LIMIT_VALIDATE_PER_MIN` (read the code for its default and use that value) to `render.yaml` and make `docs/DEPLOY.md` list `GEMINI_MODEL` as `gemini-3.5-flash-lite` and describe the new variables (`SCENE_MAX_CONCURRENCY`, `SCENE_QUEUE_WAIT_SECONDS`, `ENVIRONMENT`).
