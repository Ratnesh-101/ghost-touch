Report: docs/reports/agy-w3-buzz-fallback-report.md. Source: docs/reports/fable-win-plan.md item W3.

Problem: on a laptop or iPhone `drivers.haptics.vibrate` does nothing, so a judge dragging a mouse along the triangle hears and sees nothing on the sides.

Build, in this order:
1. frontend/src/drivers/haptics.ts: a `FallbackHapticDriver implements HapticDriver` (supported=false, lastResult tracks whether a buzz was produced). Constructor takes a small `BuzzSink` interface `{ buzz(durationMs: number): void }` and an optional `onPulse(kind)` callback. `vibrate(n | number[])`: a number n -> one buzz of n ms; an array is [on, off, on, ...] -> a buzz for each ON entry at the matching offset (setTimeout, cleared by `stop()` and by `vibrate(0)`); `vibrate(0)` cancels. Never throws. It uses the engine's own durations unchanged. Also export a pure helper `patternToBuzzes(pattern): {atMs:number; durationMs:number}[]` so it can be tested without timers.
2. frontend/src/drivers/audio.ts: add `buzz(durationMs)` to AudioDriver and WebAudioDriver: a separate short low square/sawtooth voice (about 90 Hz, gain at most 0.12, 8 ms fade in and out) that does NOT disturb the theremin oscillator or `setTone`; no-op before `unlock()`. Keep the existing AudioContextLike test doubles compiling (extend them, do not break them).
3. frontend/src/drivers/index.ts: where the drivers are created, if the web haptic driver reports `supported === false`, use `FallbackHapticDriver` wired to `audio.buzz`. When `supported` is true NOTHING changes (same object as today). `runEffects` is unchanged.
4. frontend/src/screens/Explore.tsx: when the fallback is active show (a) one visible status line, spoken once on entry: key `explore.noVibration` = "No vibration on this device. You will hear a buzz instead. Use Chrome on Android to feel it." (b) a pulse ring drawn at the pointer position for each buzz (different look for the corner pattern: two rings), via the existing canvas draw loop or a small absolutely positioned element; `aria-hidden`, `pointer-events: none`, respects prefers-reduced-motion (no animation, just a fixed ring for 120 ms). Check docs/handoffs/LOOP-CLAIMS.md first: session A owns Explore.tsx for this lane.
5. frontend/src/i18n/index.ts: `explore.noVibration` in en, hi, gu (hi/gu machine translated like the rest; add the two rows to docs/user-test/translation-review.csv).
6. Tests (new files, e.g. frontend/tests/w3.buzzFallback.test.ts and .test.tsx): patternToBuzzes for [50,90,50] gives two buzzes at 0 and 140 ms of 50 ms; a number gives one; fallback fires only when supported is false (a supported WebHapticDriver is returned untouched by the factory); `vibrate(0)` and `stop()` cancel pending buzzes (fake timers); buzz is a no-op before unlock and never touches setTone's oscillator; Explore shows the note and speaks it once when the fallback is active and not at all when vibration is supported; ring element is aria-hidden.
Constraints: TypeScript strict, no `any`, no new dependency, 48 px targets and spoken state changes as everywhere (docs: README accessibility list), no change to what Android users experience.
