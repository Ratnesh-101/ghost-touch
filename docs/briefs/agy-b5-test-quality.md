# Lane b5-test-quality (AUDIT ONLY)
Read `docs/briefs/audit-b-common.md` first. Report: `docs/reports/audit-b5-test-quality.md`.
Scope: are the tests real? Property tests are a Kiroween judging point, so check `frontend/tests/*.prop.test.ts`, `backend/tests/*_props.py` and the unit tests. Look for: assertions that cannot fail (tautologies, `expect(true)`, comparing a value with itself, generators that only produce trivial inputs, `fc.pre` filtering out almost everything, tiny `numRuns`, seeds fixed so nothing varies), properties that re-implement the function under test, mocked-away logic, snapshot tests that hide behaviour, tests that never run (skipped, excluded, wrong glob, `describe.skip`), duplicated property numbers or numbering gaps versus `design.md` (P1..P46), requirements with no test, and code paths with no test (list the top ten by risk). For five properties of your choice, describe a concrete deliberate bug in the code that the test would NOT catch. You may run `npm --prefix frontend test` and the coverage command if one exists.
