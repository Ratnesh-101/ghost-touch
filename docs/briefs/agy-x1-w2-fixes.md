Finding 1 (HIGH, backend/app/vision/gemini.py ~35-39, docs/PRIVACY.md ~128): `_redact_secrets` only does a literal `text.replace(secret, ...)`, but PRIVACY.md promises regex scrubbing of API keys and bearer tokens in gemini.py too. Make gemini.py scrub: the configured key literally, the URL-encoded and percent-encoded forms of it, any `AIza[0-9A-Za-z_-]{20,}` Google key shape, `key=` / `api_key=` / `x-goog-api-key` query or header values, and `Bearer ...` tokens (reuse or mirror the `_BEARER` / `_SK_KEY` approach in `_openai_compat.py`; put the shared regexes in one place if that is clean). Apply it to every exception text that reaches a VisionError message or a log line in gemini.py and in the `logger.warning("All vision providers failed: %s", exc)` style calls in main.py (the VisionError message is already redacted at construction; also pass any raw `exc` that is logged through the scrubber). Tests: a fake exception whose text contains the key in plain, URL-encoded and `key=AIza...` forms must come out with no key material; ordinary error text is unchanged.
2. Finding 2 (MED, limits.py ~196-207 vs `request_client_key` ~382-392): the middleware joins duplicate X-Forwarded-For header lines with ", " but `request_client_key` uses `headers.get("x-forwarded-for")` which returns only the first line, so the rate limiter and the in-flight limiter can derive different client keys for the same request (and a client can pick a different identity for the in-flight limiter by sending two header lines). Make both use the same function and the same joined value (Starlette `Headers.getlist("x-forwarded-for")`, joined with ", "). Test with a request carrying two XFF lines and TRUSTED_PROXY_HOPS values 0, 1 and 2: both limiters produce the same key.
3. Finding 5 (LOW, image_utils.py ~133-154): the WebP header sniffer only inspects the first chunk; a valid extended WebP (RIFF/WEBP with VP8X) may carry ICCP/EXIF chunks before the image data. Parse the VP8X canvas width and height (24-bit little-endian +1 each at the documented offsets) instead of rejecting; keep the 12 MP cap and the magic-byte checks. Tests with a hand-built VP8X header (small bytes, no image data needed beyond what the sniffer reads), VP8 and VP8L still pass, and a truncated header is still rejected.
