# Audit a2-share-security
Read `docs/briefs/audit-common.md` first. Report: `docs/reports/audit-a2-share-security.md`.
Focus: security and robustness of Teacher verify & share. Files: `frontend/src/share/**`, `frontend/src/drivers/hashRoute.ts`, `frontend/src/drivers/clipboard.ts`, routing in `frontend/src/App.tsx`, `frontend/src/components/VerifiedBanner.tsx`, `frontend/src/screens/ShareError.tsx`, `frontend/src/components/teach/SharePanel.tsx`, `frontend/vercel.json`, `frontend/vite.config.ts` (PWA), CSP/headers if any.
Hunt for: any path where decoded strings reach HTML, attributes, `href`, `style`, `document.title`, speech or `aria-*` unsanitised; a `javascript:` or `data:` URL anywhere; control/bidi/RTL-override characters in names and labels (spoofing the "Verified by" line, e.g. a note that imitates "Verified by Ministry..."); homograph names; resource exhaustion (decompress cap really enforced before JSON.parse; deeply nested JSON; huge arrays; many tiny segments; NaN/Infinity/-0; numbers as strings; duplicate ids; ids like `__proto__`, `constructor`, `toString`); `Object.prototype` pollution by key merge; validator drift versus `backend/app/validate.py` (list every rule that differs); QR/URL length edge cases (exactly at the cap); `location.hash` listeners that fire repeatedly or loop with `replaceState`; the hash still sitting in browser history/analytics; Referer/URL leakage to third parties (fonts, images) while a hash is present (hash is not sent, but check `document.referrer`, `window.open`, share sheet); service worker caching of `/#s=` navigations; open redirect or origin spoofing in `shareUrl(origin)`; clipboard/Web Share failures swallowed silently; the honesty copy "verified is not cryptographic proof" present on every verified surface (banner, share panel, spoken line?).
