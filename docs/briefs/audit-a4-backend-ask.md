# Audit a4-backend-ask
Read `docs/briefs/audit-common.md` first. Report: `docs/reports/audit-a4-backend-ask.md`. Backend only; do NOT run pytest/ruff (the supervisor does); you may read tests.
Focus: `backend/app/ask.py` (target parsing and validation, prompt), `backend/app/main.py`, `backend/app/middleware.py`, `backend/app/limits.py`, the Ask tests.
Hunt for: prompt injection through scene labels or the question steering the model into returning an arbitrary target or leaking the prompt; element ids that contain quotes/newlines breaking the id list in the prompt (JSON-escaped?); `parse_model_ask_output` accepting oversized JSON, nested JSON, duplicate `answer` keys, a `target` of an unexpected type; `validate_ask_target` edge cases (whitespace, case, unicode confusables, bool as number, NaN/inf strings, x/y at exactly 0 and 1, ints); target pointing to an element the frontend cannot resolve (segment/polyline/bar ids: does the frontend `resolveTarget` handle each kind the server may return?); `answer` text from the model being spoken unsanitised (length cap, control characters); response model drift between `AskResponse` and `frontend/src/api/ask.ts` `parseAskResponse`; backwards compatibility with old cached clients; scene size limits on /ask versus /scene; rate limiting and concurrency on /ask; logging of question text (privacy); timeouts and the fallback when the provider chain fails (does a target ever survive a fallback answer?); lang handling for hi/gu.
